THREE PRACTICAL CHECKS

Start with the cause, not the score.

01

Let parsing continue

A classic external script with defer downloads in parallel and runs after HTML parsing. It does not remove render-blocking CSS.

02

Reserve image space

Set image width and height so the browser can calculate its aspect ratio before the file arrives, reducing layout shifts.

03

Load images at the right time

Lazy-load below-the-fold images. Keep a likely Largest Contentful Paint image eager; consider high priority only when measurements support it.

IMPLEMENTATION HTML

A more careful starting point

These patterns are useful hypotheses to test—not a guarantee of a particular score.

<!-- Classic external script: run after parsing -->
<script src="/assets/app.js" defer></script>

<!-- Likely first-view image: reserve space; don't lazy-load -->
<img src="/images/hero.avif"
     alt="A hiker looking across a mountain valley"
     width="1200" height="800"
     fetchpriority="high">

<!-- Below-the-fold image: reserve space and lazy-load -->
<img src="/images/details.avif"
     alt="Close-up of a trail map"
     width="1200" height="800"
     loading="lazy">
i

Use an accurate text alternative for meaningful images. If an image is decorative, use alt="". Confirm the actual LCP element before changing its priority.

READING THE METRICS

A score is a clue, not the whole story.

Lighthouse scores are lab results and can vary between runs. Check the opportunity details, test under comparable conditions, and consider real-user data as well.

YOUR NEXT AUDIT

Make the comparison fair.

  1. Run Lighthouse on the same deployed page before and after a focused change.
  2. Record device mode, URL, browser, run conditions, score, and key metrics.
  3. Inspect the reported opportunity; make one change, then run the audit again.
  4. Keep the actual report with your notes. Never substitute this simulator's sample values for measured results.
