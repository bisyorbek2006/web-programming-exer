FOLLOW ALONG

Make the first snapshot.

Run these commands from a terminal.

COMMAND LINE

A small, complete Git workflow

BASH 
mkdir my-first-repo
cd my-first-repo
git init -b main

# Set your commit identity for this repository
git config user.name "Your Name"
git config user.email "you@example.com"

# Create a small HTML page
cat > index.html <<'EOF'
<!doctype html>
<html lang="en">
<head>
  <meta charset="utf-8">
  <title>My first repository</title>
</head>
<body>
  <main><h1>Hello, Git!</h1></main>
</body>
</html>
EOF

git status --short
git add index.html
git status --short
git commit -m "feat: add first page"
git log -1 --oneline
!

Replace Your Name and you@example.com with your commit identity. These settings apply only inside this repository; a GitHub noreply address can help keep your personal email private.

If your Git version does not support git init -b, use git init and then run git branch -M main before committing.

CHECKPOINT 01

Before staging

Git sees the new page, but it is not included in the next commit yet.

?? index.html

?? means untracked.

CHECKPOINT 02

After git add

The page is in the staging area and ready for the next snapshot.

A  index.html

A means added; the first column indicates it is staged.

THE IMPORTANT PARTS

Know what each step records.

Git does not automatically include every file in a commit. You choose the content to stage, then create a commit from that staged snapshot.

  1. git initCreates the repository metadata in a hidden .git directory.
  2. git statusShows what is untracked, modified, and staged.
  3. git addStages the selected file contents for the next commit.
  4. git commitRecords a snapshot of staged content with author and message metadata.

AFTER THE FIRST COMMIT

Build a history that explains your work.

Make small, focused changes next—content, layout, responsive behavior—and commit each meaningful step. Check git status before staging so you know exactly what will be recorded.
