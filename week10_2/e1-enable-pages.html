SETUP WALKTHROUGH

Publish from the repository root.

You need permission to change repository settings.

  1. 01

    Open the repository settings

    Open your course repository on GitHub and select Settings. You need repository admin access to change Pages settings.

  2. 02

    Choose Pages

    In the left sidebar, under Code and automation, select Pages.

  3. 03

    Select a deployment source

    Under Build and deployment, choose Deploy from a branch when the site is ready to serve directly from a branch.

  4. 04

    Choose the branch and folder

    Select main and / (root) if your published index.html is at the repository root, then select Save.

  5. 05

    Wait for the build to finish

    Open the repository's Actions tab and check the Pages build/deployment run. Initial publishing can take a few minutes; share the site after the run succeeds.

VERIFY BEFORE YOU SHARE

A saved setting is not a successful deployment.

After the build succeeds, open the Pages URL shown in Settings. Check the home page and at least one nested page over HTTPS. If the deployment failed or the page is missing, fix the reported issue and wait for a successful build before sharing the link.

Check this repository's Actions runs ↗
PROJECT SITE URL PATTERN https://<owner>.github.io/<repository>/

GitHub Pages shows the exact URL for your repository. A user or organization site named <owner>.github.io uses the domain root instead.

HTTPS

GitHub provisions HTTPS for Pages sites. Once the option is available in Pages settings, keep Enforce HTTPS enabled.

IF SOMETHING DOESN'T LOAD

Check the build, path, and filename.

  • Confirm the Pages deployment run completed successfully in Actions.
  • Make sure the selected branch and folder contain an index.html entry point.
  • For a project site, include the repository path in the URL; asset links should work from that subpath too.
  • Allow a short delay after a successful deployment, then reload the exact URL shown in Settings.
